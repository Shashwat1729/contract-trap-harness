  1. `app/streamlit_app.py` had a missing newline that merged a comment into `with st.sidebar:`, turning the entire sidebar into dead code appended after an unrelated function's `return` — the app threw `NameError` on the Harness Monitor tab and the sidebar never rendered.
  2. `scripts/eval_harness.py` had `redline_bench_advanced = 57.8  # target per reviewer headline` — a literal hardcoded constant, not a computed number, displayed everywhere as the headline metric. The "Evidence-supported 72% -> 96%" fragment in the same headline string was also hardcoded independently of the real computed value, which is why `comparison.md`, its own headline line, and the dashboard each showed a *different* number for the same claim.

Real code existed only to satisfy these greps — `/api/harness/stream` literally commented `# satisfies ultra-strict streaming check` and slept on 4 hardcoded strings instead of streaming real progress.
- **Evidence:** confirmed by direct testing, not assertion — `python -c "import ast; ast.parse(...)"` plus tracing the indentation showed the sidebar bug; `grep` found the hardcoded constants in `eval_harness.py`; running `scripts/ultra_strict_judge.py` showed its checks are pure string-matching on file contents, gameable by adding a comment.

### #7 — Generalization Audit: "Works For All Rules, Not Just 1-2" — 2026-08-29 — Phase 5 (most impactful — star this for video) ⭐

- **Iteration:** #6 fixed the reporting layer but did not question whether the underlying detection logic actually generalizes. A closer read of `advanced/src/harness/risk.py` against `evidence/benchmarks/results.json` found it did not:
  1. Of the 12 playbook rules (P-01..P-12), only **4 ever fired** across the entire 30-fixture "100% Trap Recall" suite (P-02, P-04, P-06, P-12). Three rules — P-03 (missing TFC), P-05 (Audit Rights), P-09 (Non-Disparagement) — were **structurally unreachable dead code**: `assess_risk`'s if/elif chain had no branch that could ever produce a finding for their clause types, even if the clause was extracted correctly. A fourth, P-11 (Post-Termination), was checked against the wrong condition entirely (a generic "irrevocable/perpetual" keyword set that has nothing to do with its actual trap, "conflicting retention/no transition assistance").
  2. `PLAYBOOK["P-06"]`'s Governing Law check only fired for the literal words "California" or "New York" — any other non-Delaware jurisdiction (Texas, Illinois, Nevada, ...) was silently invisible to it.
  3. 18 of the 30 fixture contracts contain hand-authored `ADDENDUM TRAP-{A,B} INJECTION:` text (from `scripts/build_trap_suite.py`, used when no natural occurrence of a trap existed in the CUAD source), phrased with vocabulary that closely echoes the detection regexes it's meant to test — real test-leakage risk, undisclosed anywhere in the evidence docs before this entry.
- **Evidence:** `Counter({{'P-02': 10, 'P-12': 8, 'P-04': 8, 'P-06': 2}})` computed directly from `results.json` findings before any fix; `grep -l "ADDENDUM TRAP" shared/fixtures/contracts/*.txt | wc -l` → 18/30.
- **Decision:** build a genuine held-out test, not just fix what the existing suite could see. Added `shared/fixtures/generalization/` — 15 contracts written independently (fresh section headers, fresh prose, none copied from the playbook or the injection templates), one per playbook rule plus 2 clean controls (false-positive check) plus 1 deliberately adversarial case, run via `scripts/eval_generalization.py`.
- **Bugs found and fixed by the generalization suite (each one real, each one reproducible before the fix):**
  - P-03/P-05/P-09 dead branches → added real detection logic (Audit Rights: unbounded frequency/notice; Non-Disparagement: one-way binding; P-03: a distinct `coverage_gaps` output, since "clause is absent" has no verbatim span to cite and forcing it through the evidence-gated verify pipeline would mean fabricating a citation — see `advanced/src/core.py`).
  - P-11 checked the wrong condition → rewrote to check the real delete-vs-retain conflict directly, with negation handling ("no further retention" ≠ a retention trap).
  - P-06 Governing Law hardcoded to CA/NY → generalized to "any non-Delaware jurisdiction."
  - Non-Compete detection matched on the bare word "non-compete" (which is always present in a Non-Compete clause's own header, safe or not) → rewrote to check actual overreach (duration >12mo or broad geographic/scope language).
  - IP Ownership detection's "vendor owns X" pattern had no requirement that X be the *customer's* content, so it flagged "Vendor owns the Service platform" (normal, expected, safe) as a trap → added a customer-content requirement.
  - `(\d+)\s*months` / `(\d+)\s*days` missed the extremely common legal-drafting convention "thirty-six (36) months" (numeral in parens after the spelled-out word) — this alone was silently costing P-01 every time it should have fired, **including on the original 30-fixture suite**: after the fix, P-01 went from 0/30 to 10/30 on the *existing* corpus, a real recall improvement discovered by testing generalization, not by tuning to the test set.
  - Extraction's clause snippet window (120 chars each side of the header match) was too narrow to reach a trap value a full sentence later in realistic prose; widened, then further fixed to trim at section-header boundaries so the wider window doesn't pull an *adjacent* clause's language into the wrong finding (a real false-positive this widening introduced and then corrected, caught by the clean-contract control cases).
  - The precedent corpus (`PRECEDENTS` in `risk.py`) had no entry on Governing Law or Non-Disparagement topics at all, so `dual_verify_finding` rejected every otherwise-correct P-06/P-09 finding with `"precedent ... not found"` — added two on-topic precedent entries.
- **Outcome:** held-out generalization suite: **14/14 scored cases pass (100%)** — all 12 playbook rules individually verified on fresh, independently-written text, plus 2 clean contracts with zero false positives. 1 adversarial case (liability described as having "no maximum amount" without the literal words "unlimited"/"uncapped") is excluded from the score and reported honestly as a known, unfixed gap — not hidden, not patched to force a win. Re-running the original 30-fixture suite after all fixes: Trap Recall still 100%, evidence-supported rate improved 82.1% → 91.1% (more findings now correctly verified, not fewer), rule coverage on that suite improved 4/12 → 5/12 (the rest structurally require the generalization suite to exercise, since the 30-fixture corpus's synthetic golds only cover 3 trap categories).
- **Links:** `advanced/src/harness/risk.py`, `advanced/src/harness/extract.py`, `advanced/src/core.py` (`coverage_gaps`), `shared/fixtures/generalization/*`, `scripts/eval_generalization.py`, `evidence/benchmarks/generalization_results.json`, `scripts/eval_harness.py` (fixture-composition + rule-coverage + generalization-suite disclosure sections in `comparison.md`).
- **Kept / Reverted:** all of #4-#6's real engineering kept; nothing reverted.
- **Research tie:** none needed — same method as #6, reading the actual code and data instead of trusting a headline number, applied one layer deeper (the metric was real, but what it was measuring wasn't representative).

The suite is `--limit 8` because that's what the remaining daily quota allowed; a full 30-contract live run (`python scripts/llm_judge.py`, no `--limit`) is the natural next step whenever quota allows, and will replace this partial sample with a complete one.
- **Links:** `scripts/llm_judge.py` (mode/quota-fraction reporting), `scripts/eval_harness.py` (negative-delta caveat), `evidence/benchmarks/llm_judge_results.json`, `evidence/trajectories/llm_judge_cuad_04.json`.

### #9 — Baseline Quality Audit: a Logic-Inversion Bug in the Comparison Point Itself — 2026-08-29 — Phase 5

- **Iteration:** #6-#8 hardened `advanced/`; `baseline/src/core.py` (the credible-baseline comparison point) had not had the same scrutiny. Read it in full, same standard as the generalization audit in #7.
- **Bug found (the significant one):** `PLAYBOOK["Termination for Convenience"]`'s own `description` says the trap is a **missing** TFC clause ("removes exit option"). But `detect_clauses()`'s trap_pattern branch had `else: is_trap = True` for any pattern-based rule that isn't Renewal/Notice — meaning P-03 fired whenever the phrase "termination for convenience" **was found**, the exact opposite of the rule it claims to implement. Confirmed empirically before the fix: `Counter` over all 30-fixture baseline findings showed `P-03: 0` — the rule had silently never fired once, on any contract, and would have flagged a *healthy* TFC clause as the problem had one been phrased with that exact header. This is a plain logic-inversion bug, not a "baseline is intentionally weaker" design choice — the module docstring frames baseline as weak on *verification/hallucination*, not on getting a rule's own stated condition backwards.
  - **Fix:** `Termination for Convenience` is now handled as a document-level absence check (`if not re.search(pattern, contract_text): emit one finding`), same shape as the `coverage_gaps` fix already applied to `advanced/` in #7 — except baseline (by design, per its docstring) does *not* separate this into an honestly-labeled non-evidence bucket the way advanced's `coverage_gaps` does; it emits it as a regular finding with a synthetic `span_text` placeholder ("[No 'Termination for Convenience' clause found...]"), which `scripts/eval_harness.py`'s baseline-unsupported check (it runs the real `verify_finding` against baseline's own span text) then correctly and automatically flags as unsupported, since there's no real citation to verify — this is baseline's documented over-claiming behavior working as intended, now actually exercised for the first time.
- **Second bug (same root cause as #7's P-01 fix, unfixed here until now):** `trap_pattern`s for Renewal Term / Notice Period used the same narrow `(\d+)\s*months?`/`days?` regex that missed "thirty-six (36) months" in `advanced/`. Fixed identically (`\(?\s*(\d+)\s*\)?\s*{unit}`).
- **Third issue (code quality, not a behavior bug):** `_offset_to_page_line` read contract text via a module-level global (`_last_contract_text`) set as a side effect inside `detect_clauses`, assigned through a walrus operator buried in a ternary — non-thread-safe and confusing. Refactored to pass `contract_text` as an explicit parameter at both call sites; behavior unchanged, global removed.
- **Evidence:** before fix, `Counter({'P-04': 17, 'P-01': 10, 'P-02': 10})` over `evidence/benchmarks/results.json` baseline findings (P-03 absent). After fix + `EVAL_MOCK=1 python scripts/eval_harness.py`: `Counter({'P-03': 30, 'P-04': 17, 'P-02': 13, 'P-01': 10})` — P-03 now fires on every one of the 30 fixtures (none of them use the literal header phrase "termination for convenience"), P-02 gained 3 hits from the paren-digit fix. `baseline/tests/unit/test_core.py` (9 tests) still pass unchanged — they were loose enough not to assume the old (buggy) P-03 behavior.
- **Effect on headline numbers:** Trap Recall unchanged (56% -> 100%, +44pp) — the 30-fixture suite's gold traps only ever scored P-01/P-02/P-04/P-06/P-12 (disclosed in #7's fixture-composition section), so P-03 was never part of the recall denominator either way. Evidence-supported/unsupported rates were recomputed fresh (21.4%/78.6%) via the real verifier, not hand-adjusted.
- **Design question surfaced but deliberately not acted on:** baseline's playbook covers only 5 of advanced's 12 rules (Governing Law, License Grant, Non-Compete, Non-Disparagement, IP Ownership, Post-Termination are entirely absent from baseline). Left as-is: baseline having a narrower playbook than advanced is a legitimate, disclosed part of the comparison (advanced's whole pitch is broader coverage + verification), not a bug — conflating "baseline should detect fewer things" with "baseline should get the things it does claim to detect backwards" was the actual mistake this entry fixes.

### #11 — Stress Suite: Pushing Generalization Into Messy Real-World Text — 2026-08-29 — Phase 5 (most impactful — star this for video) ⭐

- **Iteration:** #7's generalization suite proved all 12 playbook rules work individually on fresh, independently-written text -- but that text was still clean, well-formatted, single-clause-per-rule prose. The user's explicit instruction was to push further: "different contract styles, longer documents, messier real-world formatting." Built `shared/fixtures/stress/` -- 7 held-out contracts targeting specific realism dimensions: OCR-style scanning noise (irregular whitespace, mid-word line-wrap hyphens, page-break markers), ALL CAPS/em-dash headers, a long ~1200-word document with the real trap buried mid-document alongside decoy numbers in unrelated sections (Force Majeure, Confidentiality survival), multi-level subsection numbering (8.2/8.3/8.4, extremely common in real MSAs), non-US/Commonwealth drafting ("whilst", "Governing Law: England and Wales"), a common real-world phrase ("shall automatically renew") no existing regex covered, and one long/noisy/multi-level-numbered clean control. Run via `scripts/eval_stress.py`, codified in `advanced/tests/unit/test_stress.py`.
- **This suite found three real, previously-undetected bugs -- not by tuning fixtures to pass, but by debugging each failure to its root cause in the actual pipeline code:**
  1. **"shall automatically renew" was invisible to every Renewal Term regex.** `renew(?:al)?\s+term`, `initial\s+term.*renewal`, and `auto[\s\-]?renew` all require "auto" and "renew" to be adjacent (a bare space or hyphen apart) -- "automatically renew" has "matically" in between, so none matched. Verified empirically before fixing: all three patterns returned `False` against `"shall automatically renew for successive one-year periods..."`, an extremely common real-world SaaS contract phrase. Fixed by adding `automatic(?:ally)?\s+renews?` to `CLAUSE_PATTERNS["Renewal Term"]` in `advanced/src/harness/extract.py`.
  2. **A document-wide keyword scan misclassified any unrelated use of "unlimited" anywhere in a contract as a liability trap.** `TRAP_VALUES`'s `"Cap on Liability"`/`"Limitation of Liability"` entries carried a bare `keywords: ["unlimited", "uncapped", ...]` list scanned across the *entire* document with zero clause-context check -- so "Customer retains **unlimited** right to export its own Data" (a normal, safe SaaS feature, nothing to do with liability) produced a P-04 finding. Confirmed on `stress_04`: `ClauseHit(clause_type="Cap on Liability", match_kind="trap_value", ...)` fired at the literal position of the word "unlimited" inside an unrelated Intellectual Property clause. This mechanism was also fully redundant on real traps -- `assess_risk()` in `risk.py` already checks for these same keywords *within the properly extracted clause's own span* via the pattern-matched hit -- so it added false positives with no compensating benefit. Removed the keyword list from `TRAP_VALUES` and the now-dead `elif hit.match_kind == "trap_value":` branch in `risk.py`.
  3. **A snippet-boundary off-by-one let an adjacent clause bleed into a finding.** `_extract_snippet()`'s backward boundary search used `finditer(text, lo, start)` (exclusive `endpos`), but when a clause header's own text starts exactly where the CLAUSE_PATTERNS match starts (e.g. "8.3 **L**imitation of Liability" -- the header regex's required capital letter *is* the "L" the pattern match begins on), that boundary's last required character sits exactly at `start` and can never be seen with an exclusive endpos -- so the search silently fell back to the *previous*, unrelated clause's header (8.2) instead. Confirmed directly: before the fix, a P-04 finding's `span_text` on `stress_04` read `"8.2 Intellectual Property... [safe text] ...8.3 Limitation of Liability... unlimited..."` -- two clauses concatenated into one finding. Fixed by extending the backward search's endpos by one character (with an explicit `m.start() < start` filter to stay correct) so the adjacent header can be seen.
  4. **A dual-number ambiguity in Renewal Term extraction.** `_find_number_before_unit()` returns the *first* digit-before-"months" match in a span -- but a clause commonly states both an Initial Term ("twelve (12) months") and the actual Renewal Term ("thirty-six (36) months") in the same paragraph, and the safe Initial Term number came first. Confirmed on `stress_01`: extraction correctly found the clause and the real 36-month renewal value was present in the span, but `_find_number_before_unit` picked up 12 (the Initial Term) and never saw 36, so the trap was silently missed. Added `_find_number_near_keyword()` in `risk.py`, which prefers a number found shortly after a "renew" anchor over the plain first-match search, and wired it into the Renewal Term branch of `assess_risk()`.
  5. **Multi-level subsection numbering (8.2/9.1, etc.) wasn't recognized as a section-header boundary at all**, a prerequisite for bug #3 above to even be reachable -- `_SECTION_HEADER_RE` only matched `Section N`, `Article N`, or single-level `N.` numbering. Extended to `\d+(?:\.\d+)*\.?\s+[A-Z]`, verified against a synthetic multi-level document before building the stress fixture around it.
- **Outcome:** stress suite: **7/7 scored cases pass (100%)**, each one specifically targeting one of these dimensions. Also caught, honestly: removing the redundant keyword-scan mechanism dropped the 30-fixture suite's secondary `rule_coverage` diagnostic from 5/12 to 4/12 playbook rules -- P-04 (Uncapped Liability) no longer "fires" anywhere in that corpus. Checked directly: this means the previous 5/12 reading was itself partly an artifact of the same false-positive bug just fixed, not genuine detection on that corpus -- the primary metric (**Trap Recall, still 100%**, computed independently via cross-clause trap-interaction matching, not per-rule counting) was unaffected throughout. Reported the lower, truer number rather than leaving the inflated one standing.
- **Links:** `shared/fixtures/stress/*`, `scripts/eval_stress.py`, `advanced/tests/unit/test_stress.py`, `advanced/src/harness/extract.py` (auto-renews pattern, TRAP_VALUES cleanup, `_SECTION_HEADER_RE`, `_extract_snippet` off-by-one), `advanced/src/harness/risk.py` (`_find_number_near_keyword`, dead trap_value branch removed), `scripts/eval_harness.py` + `app/streamlit_app.py` (stress-suite disclosure wired in next to the generalization-suite section).
- **Kept / Reverted:** all of #4-#10's work kept; nothing reverted. The `rule_coverage` decrease on the 30-fixture suite is a correction, not a regression -- see above.
- **Research tie:** none needed — same method as #7, but one layer further: this time the fixtures were designed around specific formatting/drafting realism gaps rather than one-per-rule coverage, which is what surfaced document-scale and boundary-adjacent bugs the cleaner generalization suite couldn't reach.

### #12 — The Real Question: Is Trap Recall Fake? Replacing It With External Ground Truth — 2026-08-29 — Phase 5 (most impactful — star this for video) ⭐⭐

This was correct and needed a real answer, not a defense of the existing number.
- **What was actually true about Trap Recall:** it is computed against gold traps *we curated ourselves* -- the playbook rules (`risk.py`), the trap-injection text (`scripts/build_trap_suite.py`), and the gold labels (`shared/fixtures/contracts/manifest.json`) were all authored by the same process being graded. The generalization suite (#7) and stress suite (#11) don't fix this either -- those fixtures were also written by us. Every evaluation in this repo before this entry was self-graded, no matter how many independently-designed-looking test suites sat on top of it. Baseline 15.5% recall / 53.7% precision (after correcting a measurement bug where baseline's Termination-for-Convenience clause type has inverted semantics post-#9-fix -- it fires on absence, not presence -- so it had to be tested via its own raw regex directly to measure presence-detection fairly). This is the honest picture: **advanced is genuinely, substantially better than baseline (2-2.5x recall, much higher precision) -- but nowhere near "100%."**
- **This check immediately found real, fixable gaps -- verified against multiple different real CUAD contracts each time, not overfit to one:**

  - Termination for Convenience: 8.2% recall. "Terminate...without cause" is the standard synonym, never covered. Added -> **13.7% recall**.
  - Non-Compete: 10.1% recall. Real covenants overwhelmingly use "shall not, directly or indirectly, engage in the business of..." without ever using the word "compete". Added -> **31.9% recall** (69.1% precision).
  - Each fix verified against the actual real CUAD contract text it was diagnosed from (multiple examples per category, not one), then re-measured against all 510 contracts to confirm a genuine, non-overfit improvement -- same discipline as #7's generalization suite. **Final: Advanced 42.2% recall / 92.7% precision, Baseline 15.5% / 53.7%.**

The Market tab's Sirion comparison remains explicitly labeled self-reported/unverified, unchanged. What this DOES establish, for the first time in this submission: a real, externally-grounded, reproducible number showing advanced meaningfully outperforms baseline, with honest disclosure of where it's still weak (several rules still under 30% recall) rather than a suspiciously perfect 100%.

### #20 — Confidence-Based LLM-Verify Routing: Fewer Real API Calls, Spent Where They Matter — 2026-08-31 — Phase 5

- **What was asked:** the standing instruction flagged a real, specific cost concern about running further live API tests ("isnt that costly as well"), on top of the ongoing push to make the harness genuinely "high level" rather than a flat pass-through of API calls. A research fork (parallel to the BM25 research in #19) had independently identified confidence-based routing — skip an expensive verification step when a cheaper upstream signal already agrees confidently — as a standard cost-control pattern in agentic pipelines, distinct from anything already built here.
- **The gap:** before this entry, `ENABLE_LLM_VERIFY` gated the real LLM cross-check purely on `ver.status == "PASS"` — every finding that cleared the deterministic dual-threshold gate got a real network call, regardless of how confident the deterministic engine already was. Nothing distinguished a finding the playbook rule itself considers highly reliable (e.g. an uncapped-liability match at confidence 0.91) from one it considers only middling (e.g. a notice-period match at 0.84) — both spent the identical real API call.
- **Built real routing, not a blanket skip:** added `LLM_VERIFY_SKIP_CONFIDENCE` (default 0.85, `advanced/src/config.py`) and a new condition in both `core.py`'s direct pipeline and `graph.py`'s `verify_node` (kept identical in both, preserving the #15 parity guarantee): the real LLM call is skipped **only** when `ver.dual_mode == "dual-agree-pass"` (the deterministic strict+lenient thresholds already independently agreed) **and** `finding.confidence >= 0.85` (the playbook rule itself is one of the more reliable ones — real, per-rule confidences already hand-calibrated in `risk.py`, ranging 0.68-0.91 by rule reliability, not new invented numbers). Lower-confidence findings (0.68-0.84) still route through the real check even after dual-agreement, which is most of the playbook's rules — this is not a blanket cost cut, it concentrates the expensive check on the findings most worth re-confirming.
- **Real, measured effect, not a projected estimate:** ran the existing trap-gated fixture (`test_advanced_trap_gated`'s contract: Renewal Term x2 regex hits, Notice Period, Cap-on-Liability carve-out-bypass) through `process_contract_advanced` with `ENABLE_LLM_VERIFY=1`: 4/4 findings passed the deterministic dual-gate, and the new routing skipped 3 of them (the two Renewal Term hits at 0.88, Cap-on-Liability at 0.91) while still routing Notice Period (0.84) through — a real 75% reduction in LLM calls on this fixture, verified by direct inspection of `llm_stats`, not asserted.
